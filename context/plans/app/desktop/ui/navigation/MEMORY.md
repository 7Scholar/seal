## 2026-08-02 — The title bar drags because of `data-tauri-drag-region="deep"`, and CSS app-region does nothing

Window dragging is decided by a framework-injected script that walks the composed path of each mouse press; the CSS `app-region` property is **not** consulted, and this webview discards the declaration at parse time — measured, it does not survive into `cssRules` and reads back empty from `getComputedStyle` in both a working and a broken build. The strip carries the `deep` value because a bare attribute drags **only on a direct press of that exact element**, and everything a user presses in the strip — the breadcrumb trail, the current segment, the empty space — is a child of it. **Why:** the shipped strip had the bare attribute and looked correct in the markup while being dead everywhere a person would actually grab it. **Mistake it prevents:** "simplifying" `deep` back to a bare attribute because the bare form is what every example shows; or adding `-webkit-app-region: no-drag` rules for the strip's buttons, which is inert CSS that appears to be load-bearing — interactive children already exclude themselves, because the same walk stops at the first clickable element it meets.
