Part of [the engine plan](README.md).

# Scope

The sealed-file format and the binding to the age library: producing an armored age file with a single scrypt passphrase stanza at an explicitly pinned work factor, reading one back, and classifying a path as sealed, plaintext, or absent without a passphrase. Out of scope: writing files to disk (`replace.md`'s job) and the public operations that compose these (`operations.md`).

# What exists

The format binding, classification, and the work-factor constants, implemented and verified.

**The work factor is measured, not guessed.** A release build on current hardware costs roughly 20 ms at factor 14 and doubles per step: 166 ms at 17, 331 ms at 18, 662 ms at 19. New files are sealed at **18**, landing in the few-hundred-millisecond band the Approach asks for. The accepted floor is **15** (about 41 ms), chosen well below the writing constant so files sealed by an older Seal or by stock tooling on slower hardware still open, while a file sealed far weaker than Seal would ever write is refused rather than silently accepted. The ceiling is **22**, guarding against a file engineered to force an enormous derivation. A compile-time assertion pins the invariant that Seal never writes files its own floor would reject.

Sealing takes a reader, a writer, a passphrase and a work factor, and emits an armored age file with a single scrypt stanza. Unsealing takes an ordered list of candidate passphrases and reports which one opened the file, along with the work factor the file carried.

**Unsealing streams, and requires a seekable input to do so.** Trying several candidate passphrases needs more than one pass over the file, because constructing a decryptor consumes both the reader and the decryptor itself. Rather than buffer the file to allow retries, the input is rewound between attempts: each candidate reads only the header, and only the candidate that matches goes on to stream the payload. Plaintext therefore never exists in memory as a whole, and the chunk buffer it passes through is wiped when released. The seekable requirement costs callers nothing, since every real caller is reading a file.

Classification reads only the opening bytes and distinguishes armored-sealed, binary-sealed, and plaintext without a passphrase; binary is recognised although Seal never writes it, because stock tooling does. Reading the work factor goes through the armor decoder rather than scanning raw lines, for the reason recorded in `MEMORY.md`.

Errors distinguish the cases a user experiences differently: no candidate opened it, not a sealed file at all, damaged or truncated, sealed too weakly, sealed too expensively.

Verified by twelve behavioural tests and eight vector tests: round-trips across empty, ordinary, multi-chunk and multibyte content; armored framing; the work factor read back from the file; the reported candidate index; wrong passphrase distinguished from a corrupted payload; the floor enforced; plaintext not mistaken for sealed; every classification shape including an empty file and one that merely mentions the marker mid-file; and that a multi-megabyte payload reaches its sink in chunks rather than as one buffer, which is what makes the streaming claim verifiable rather than asserted. The floor and the compile-time invariant were both confirmed non-vacuous by breaking them.

**Interoperability with the reference implementation is proven in both directions.** A file Seal writes opens with the stock Go `age` binary, a file that binary writes opens with Seal, and the committed corpus is readable by it — which is what turns the corpus from evidence of self-consistency into evidence of interoperability, since the corpus is otherwise generated by the same library the engine uses. This is the guarantee the whole format choice rests on, so it is verified against a genuinely independent implementation rather than a second wrapper over the same crate.

The stock binary refuses to read a passphrase from anything but a terminal, so the tests drive it through a pseudo-terminal. They skip with an explanatory message — rather than failing — when the binary is absent, and equally when the environment allows no pseudo-terminal to be allocated, which a sandbox or container can refuse even with the binary installed. Either way a contributor gets a green suite without installing or configuring anything, while the coverage stays real wherever both are available. The variable that marks a run as requiring interoperability turns **both** skips into loud failures, so the guarantee can never go silently unverified where it is supposed to hold.

Nothing. The remaining engine work sits in `operations.md`.

# Open threads

- The continuous-integration pipeline installs a version-pinned stock `age` binary and sets the variable that turns a skip into a failure, so the guarantee cannot go silently unverified. Revisit the pinned version deliberately rather than floating it, since a floating version turns an upstream change into a mysterious failure.
- Classification takes a reader, and the operations layer passes it the same open handle it goes on to use, rewinding afterwards — so the Approach's requirement is met at the layer that opens files rather than by the format module holding a handle it does not own.
