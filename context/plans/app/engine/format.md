Part of [the engine plan](README.md).

# Scope

The sealed-file format and the binding to the age library: producing an armored age file with a single scrypt passphrase stanza at an explicitly pinned work factor, reading one back, and classifying a path as sealed, plaintext, or absent without a passphrase. Out of scope: writing files to disk (`replace.md`'s job) and the public operations that compose these (`operations.md`).

# What exists

The format binding, classification, and the work-factor constants, implemented and verified.

**The work factor is measured, not guessed.** A release build on current hardware costs roughly 20 ms at factor 14 and doubles per step: 166 ms at 17, 331 ms at 18, 662 ms at 19. New files are sealed at **18**, landing in the few-hundred-millisecond band the Approach asks for. The accepted floor is **15** (about 41 ms), chosen well below the writing constant so files sealed by an older Seal or by stock tooling on slower hardware still open, while a file sealed far weaker than Seal would ever write is refused rather than silently accepted. The ceiling is **22**, guarding against a file engineered to force an enormous derivation. A compile-time assertion pins the invariant that Seal never writes files its own floor would reject.

Sealing takes a reader, a writer, a passphrase and a work factor, and emits an armored age file with a single scrypt stanza. Unsealing takes an ordered list of candidate passphrases and reports which one opened the file, along with the work factor the file carried. Classification reads only the opening bytes and distinguishes armored-sealed, binary-sealed, and plaintext without a passphrase; binary is recognised although Seal never writes it, because stock tooling does. Reading the work factor goes through the armor decoder rather than scanning raw lines, for the reason recorded in `MEMORY.md`.

Errors distinguish the cases a user experiences differently: no candidate opened it, not a sealed file at all, damaged or truncated, sealed too weakly, sealed too expensively.

Verified by twelve behavioural tests and eight vector tests: round-trips across empty, ordinary, multi-chunk and multibyte content; armored framing; the work factor read back from the file; the reported candidate index; wrong passphrase distinguished from a corrupted payload; the floor enforced; plaintext not mistaken for sealed; every classification shape including an empty file and one that merely mentions the marker mid-file. The floor and the compile-time invariant were both confirmed non-vacuous by breaking them.

# What is missing

Interoperability tests against a real stock `age` binary. The committed vector corpus gives hermetic regression coverage, but it is generated by the same library the engine uses, so it cannot prove interoperability on its own — only a real second implementation can, and that is the outstanding step.

# Open threads

- **Unsealing currently buffers the whole file rather than streaming it.** Retrying several candidate passphrases needs more than one pass over the input, and the simplest way to get that was to read the bytes into memory once. This contradicts the Approach's streaming promise, and for a large managed file it means memory proportional to size. Two ways out: require a seekable input so each attempt can rewind, or resolve the passphrase against the header alone and stream the payload only once a candidate is known to match. The second is better and matches how the header and payload are actually separated; settle it before the operations layer depends on the current shape.
- The passphrase-entry mechanism for driving a real `age` binary in tests is awkward (it reads from the terminal rather than standard input); settle it when the interoperability job is written. Note also that no stock `age` binary is installed on this machine, so that job must install a pinned one rather than assume it.
- Classification currently takes a reader. The Approach calls for it to operate on an already-open handle shared with the subsequent operation, so that a file cannot be swapped between classifying and acting; wire that through when the operations layer opens files.
